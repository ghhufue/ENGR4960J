# 工程伦理分析平台 UI Design System

## 1. 设计定位

风格：**浅色、简约、专业，适合长时间阅读和反复推敲的分析工作台。** 以 Linear / Notion 风格作为方向参考，采用清晰导航、克制强调色、文档式阅读和紧凑列表；本规范是为本项目制定的独立设计，不是上述产品的官方规范。

适用范围：案例概览、完整 10 步分析、来源库、过程与反思、完成检查和课堂展示模式。本阶段只制定视觉和组件规范，不编写 HTML、CSS 或其他实现代码。

交互依据：[10 步交互设计](html-interaction-design.md)、[点选交互清单](html-choice-interaction-design.md)。本规范决定界面如何呈现，字段、选项和判断规则仍由这两份文档定义。

### 设计原则

1. **分析内容优先**：标题、问题、依据和用户说明占据主要空间，状态和操作放在稳定位置。
2. **先选择，再深入**：固定选项直接可见，开放说明按选择展开，来源和高级信息按需查看。
3. **通过排版建立层级**：以字重、间距、细分隔线区分内容，少用厚边框、大阴影和整块彩色背景。
4. **判断可追溯**：事实、假设、未来情景有明确类型标签；选中、已保存和已复核使用不同标识。
5. **便于返回修改**：导航、关联对象和返回入口始终清楚，不把页面设计成只能向前的问卷。

建议整体视觉比例：大部分区域保持中性色，靛蓝只用于当前位置、选中项、链接和主要动作；语义色只用于对应状态。比例是风格倾向，不是需要逐像素统计的指标。

### 2.2 语义色

| 语义 | 文字/图标 | 浅背景 | 对应内容 |
| --- | --- | --- | --- |
| 已复核或确认完成 | #166534 | #F0FDF4 | 组员已确认的复核状态、成功操作反馈 |

### 2.3 分析记录类型

| 类型 | 文字色 | 浅背景 | 必须显示的文字 |
| --- | --- | --- | --- |
| 事实 | #1D4ED8 | #EFF6FF | 事实；核查状态另列 |
| 假设 | #6D28D9 | #F5F3FF | 假设；不能因为暂时采用就改成事实标签 |
| 未来情景 | #0F766E | #F0FDFA | 未来情景 |
| 问题、术语、原则、方案、约束 | #4B5563 | #F3F4F6 | 各自类型名称和编号 |

| 辅助文字 / 工作区底色 | 4.68:1 |
| 辅助文字 / 导航底色 | 4.52:1 |
| 白字 / 主强调色 | 6.29:1 |
| 选中文字 / 选中底色 | 8.88:1 |
| 交互边界 / 白色内容表面 | 3.62:1 |

| 错误文字 / 对应浅背景 | 5.91:1 |

状态必须同时有文字和图标。选中状态必须有单选圆点、勾选标记或当前位置标识，不能只改变背景色。后续改色、增加透明度或换底色时需重新校核。

### 2.5 深色模式

在顶部栏提供太阳/月亮图标按钮，用于切换亮色与深色；默认亮色，后续恢复当前浏览器保存的选择。按钮的可读名称为“深色模式”，按下状态表达当前是否启用深色，悬停说明显示将切换到的模式。

深色不是整体反色，而是保留同一组件和语义，对应调整表面、文字与状态色。展示模式、导航、表单、关联材料、弹层和反馈共用当前主题。切换不重建编辑区，也不改变分析数据、完整性检查或人工复核状态。

## 3. 字体与文字层级

### 3.1 字体方案

- 英文和数字：优先使用已打包的 Inter；未提供时使用 Segoe UI 或系统无衬线字体。
- 中文：使用系统可用的中文无衬线字体，例如 PingFang SC、Microsoft YaHei、Noto Sans CJK SC。
- 编号、日期、统计数：优先使用同一正文家族，数字保持整齐对齐；确需区分代码位置时再使用 Consolas 或系统等宽字体。
- 首版采用系统字体即可；不要把联网字体加载作为页面正常阅读的前提。

实际混排需以中文内容为主检查；不要为了英文标题外观给中文正文设置过大的字距。案例正文不使用装饰衬线字体。

### 3.2 字号、行高和字重

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面主标题 | 26 / 36 px | 600 | 案例概览、步骤主标题、来源库标题 |
| 区块标题 | 18 / 28 px | 600 | 伦理问题列表、合理假设、方案区 |
| 记录标题 | 15 / 24 px | 600 | 问题、事实、术语或方案标题 |
| 阅读正文 | 15 / 24 px | 400 | 用户分析内容、长说明 |
| 控件与导航 | 14 / 20 px | 400；当前项 600 | 按钮、选项、导航和表格 |
| 字段标签 | 13 / 20 px | 500 | 输入框和选项组名称 |
| 帮助与提示 | 13 / 20 px | 400 | 字段引导、缺项说明 |
| 元信息 | 12 / 18 px | 400 | 编号、来源位置、保存时间、英文步骤副标题 |

默认不用小于 12px 的正文信息。主标题最多两行，长案例名可在顶部截断并提供完整名称，但当前编辑对象的标题在正文中正常换行。

中文步骤名称作主标题，英文名称作副标题，不把所有英文名称写成全大写。段落之间留 12px；长分析说明的阅读宽度建议控制在约 640–720px，结构化表格可更宽。

## 4. 页面布局与响应式规则

### 4.1 桌面工作台

| 区域 | 规范 | 内容 |
| --- | --- | --- |
| 全局顶部栏 | 高 56px，白底，底部细线 | 项目名、保存状态、备份菜单、展示模式 |
| 左侧导航 | 宽 240px；中等桌面可缩为 224px | 案例概览、10 步、来源库、过程与反思、完成检查 |
| 中央工作区 | 自适应；宽屏内层内容最大 960px | 步骤标题、选择与说明、记录列表、编辑区 |
| 右侧参考区 | 宽屏打开时宽 320px，白底、左侧细线 | 关联记录、来源摘录和待补内容 |
| 步骤操作栏 | 高度约 64px，白底，顶部细线 | 上一步、检查本步、标记已复核或下一步 |

右侧参考区不是强制常驻：默认收起，可从“查看关联材料”或关联标签打开。1440px 屏幕展开参考区时，240px 导航 + 880px 中央区 + 320px 参考区构成完整三栏；中央左右各留 32px 后仍有 816px 内容宽度。

中央区优先一个主要内容列。短期/长期方案等天然并列内容才使用两列；任何一列不足约 280px 时回到上下排列。不要把所有步骤都做成两列密集表单。

### 4.2 屏幕适配

| 视口宽度 | 布局规则 |
| --- | --- |
| 1440px 及以上 | 240px 导航；参考区可作为 320px 侧栏展开；中央边距 32px |
| 1024–1439px | 224px 导航；参考区改为按需抽屉；中央边距 24px |
| 768–1023px | 默认隐藏导航，由顶部菜单打开；中央单列，边距 24px；参考材料用抽屉查看 |
| 小于 768px | 单列，边距 16px；导航用抽屉；参考详情接近全屏；并列方案改为上下两块 |

普通编辑区不出现页面级横向滚动。复杂对比表允许在自己的区域横向滚动，并显示滚动提示。窄屏导航必须直接显示当前步骤，不能只留下一个没有上下文的菜单图标。

### 4.3 滚动与固定区域

默认中央内容随页面滚动；桌面导航可独立滚动，参考区打开后可独立查看长来源。顶部栏固定，步骤操作栏可在工作区底部吸附，但正文底部至少预留 80px，避免覆盖最后一个输入框。

窄屏操作栏按钮可换行，不强制把 4 个动作塞进一行。弹出软键盘时，以正在编辑的字段可见为优先，必要时取消底栏吸附。

## 5. 间距、尺寸与形状

### 5.1 间距

采用 4px 基础节奏，常用值如下。

| 数值 | 主要用途 |
| --- | --- |
| 4px | 图标与短标签、状态元素内部微间距 |
| 8px | 选项之间、标签之间、按钮之间 |
| 12px | 段落间距、紧凑行内边距、小区块内的辅助分隔 |
| 16px | 卡片内边距、字段组间距、移动端页面边距 |
| 24px | 章节内部区块间距、常规表单卡片内边距 |
| 32px | 页面大区块间距、宽屏内容边距 |
| 48px | 空状态和概览页较大的上下留白 |
| 64px | 页面内容与较大说明区域的分隔，不作为常规字段间距 |

字段内部统一：标签下方 8px 到控件，控件下方 4px 到帮助或错误信息；同一区块中的字段之间 16px，完整区块之间 32px。

### 5.2 尺寸和圆角

| 元素 | 默认尺寸 / 圆角 |
| --- | --- |
| 常规按钮 | 高 36px，水平内边距 12–16px，圆角 6px |
| 常规输入与选择器 | 高 40px，圆角 6px |
| 选项按钮 | 最低高 36px，短标签圆角 6px；长说明卡圆角 8px |
| 移动端可点目标 | 最低 44px 高；图标可小于目标区域 |
| 导航行 | 高 36px，圆角 6px |
| 分析卡片 | 圆角 8px，内边距 16px；复杂编辑卡可用 24px |
| 弹层与详情抽屉内部面板 | 圆角 12px；贴边抽屉的外沿保持平直 |
| 状态与类型标签 | 视觉高 24px，圆角 4px；不可操作标签无需做成大按钮 |
| 多行输入 | 默认高 96px，可扩展；长分析按内容增高 |

避免所有元素都做成胶囊。只有短小的计数或少数紧凑标签可使用胶囊样式，选项与按钮仍保持略方的工作台形态。

### 5.3 边框与层次

普通内容使用 1px 分隔线；输入和选项使用 1px 交互边界；焦点为 2px 靛蓝轮廓并与边界留约 2px 间隔。弹层可使用柔和阴影表达浮起，普通分析卡片默认无阴影。

页面本身的空白和标题已经建立分组时，不再把每段内容都套进卡片。优先使用“标题 + 内容 + 下方分隔线”，需要编辑边界或对象关系时才用卡片。

## 6. 页面与信息层级

### 6.1 导航结构

| 层级 | 名称 | 呈现方式 |
| --- | --- | --- |
| 全局 | 当前案例、小组、保存和项目操作 | 顶部栏，不混入每条记录 |
| 一级页面 | 案例概览 / 10 步分析 / 来源库 / 过程与反思 / 完成检查 | 左侧导航分组 |
| 步骤页面 | 01–10 的各分析步骤 | 编号、中文短名、状态图标；不折叠为难发现的二级树 |
| 内容区块 | 问题列表、事实类别、方案、约束等 | 区块标题、必要说明、区块级操作 |
| 分析对象 | 一条问题、事实、假设、术语等 | 编号、类型、标题、内容、关联与状态 |
| 辅助细节 | 来源摘录、变更说明、归档历史、次要设置 | 参考区、折叠区或更多菜单 |

导航分为三个视觉组：案例概览；10 步分析；来源与过程等支撑页面。组之间留 16–24px，不为每组添加醒目的彩色大标题。

10 步导航均可访问。当前步骤用选中底色、选中文字、字重和左侧短标记表达；已复核与待复核使用右侧状态图标，并提供文字解释。状态图标不能取代步骤名称。

### 6.2 步骤页面的阅读顺序

1. 页面路径或步骤编号。
2. 中文主标题、英文副标题和本步状态。
3. 一句本步目标；更长的引导放入“思考提示”折叠区。
4. 本步主要输入：先选择，再补说明。
5. 已有记录列表、关联材料入口和必要检查结果。
6. 本步重要性说明等较长文字，保持清楚标题，可按需展开。
7. 步骤操作栏。

默认展开“正在处理的内容”；其余已有记录可先显示摘要。必要字段即使未展开，也要在检查结果里可定位，不能用折叠掩盖缺项。

### 6.3 对比展示的优先级

桌面宽度足够时，短期/长期方案并列；事实/假设或两条候选方案用明确标题并排，按行对应。窄屏改成顺序区块，重复显示对象名称，避免用户滚动后分不清当前在看哪一项。

## 7. 基础组件规范

### 中英文切换

顶部栏提供独立 `EN / 中文` 按钮，文字显示可切换到的语言。按钮最小宽 44px，采用次级文字与中性悬停底色，与主题切换并列。界面默认中文并恢复浏览器保存的语言选择。

英文界面保持原配色、字号和信息层级；导航标题允许换行，桌面顶部空间不足时隐藏次要案例名，窄屏备份和展示动作使用带可读名称的图标按钮。字段标签、选项、引导、状态、弹窗、检查结果、`lang` 和页面标题同时更新。

语言切换只翻译界面文案与固定选项的显示标签。用户填写的分析、名称、引用和自定义文本保留原语言；当前编辑记录、筛选与展开状态保留。亮色、深色和展示模式均使用同一语言选择。

### 7.1 按钮与文字操作

| 类型 | 样式 | 用途 |
| --- | --- | --- |
| 主要按钮 | 靛蓝实底、白字 | 当前主要动作，例如“检查本步”；检查完成后可切为“标记已复核” |
| 次级按钮 | 白底、中性边界、深色文字 | 新增记录、上一/下一步、导出备份、取消 |
| 轻量按钮 | 默认无背景，悬停浅灰 | 展开材料、查看关联、更多操作 |
| 危险操作 | 默认红色文字；确认阶段再使用红色实底 | 永久删除、覆盖当前项目的最终确认 |
| 图标按钮 | 16px 图标、36px 点击区；移动端 44px | 关闭、展开、复制、更多菜单 |

同一操作区只保留一个高强调主按钮。自动保存模式不为每张卡片重复设置“保存”主按钮；新增或编辑完成的操作文案应说明“添加记录”“完成编辑”等实际动作。

“下一步”是导航，使用次级样式，不用绿色成功按钮；“已保存”不是主按钮。仅图标操作必须有可读名称及提示。

### 7.2 输入框、长文本与帮助

- 输入框为白底、主文字、明显中性边界；占位文字用辅助色，但字段标签始终可见。
- 长文本默认 96px 高；用户写多后增高或允许调整，不截断正在编辑的正文。
- 帮助说明放在控件下方；必要的题目说明可在控件上方，不把多行说明塞进占位符。
- 错误使用红色边界、图标和具体文字，不清空已有内容。
- 必填只对本方案真正需要的字段标注；可选字段显示“可选”，不为所有可选字段添加视觉干扰。
- 字数提示放在输入框下方右侧；中文字符和英文 words 明确区分，未确认口径时不显示“已达标”的绿色徽章。

### 7.3 单选与分段选项

2–6 个短选项直接平铺；每项包含真实单选标识、文字和点击区域。选择后使用浅靛蓝底、靛蓝边界和实心单选标识。较长选项使用纵向排列，允许文字换行。

状态字段可用分段按钮，但也需明确表达单选关系。分析判断初始无选择，不因界面需要整齐而默认选“适用”或“无冲突”。

### 7.4 多选候选

多选采用带勾选标识的短矩形选项，间距 8px，自动换行；与单选的圆点区分。默认显示常用方向，更多项通过“展开更多”呈现。

“其他，自行补充”与普通选项同等可发现，选中后在组下方展开补充框；“不适用 / 尚不确定 / 无额外措施”等单独判断保留清楚分组，互斥规则按选项清单执行。

选项被点选后只显示为“已选”，不出现绿色正确标记或答题得分。方向标签与具体说明之间留 16px，帮助用户识别第二步仍需说明。

### 7.5 搜索与关联选择器

选择器打开后显示搜索框、已有条目和“新增记录”入口。每条候选由编号、标题、类型和可选状态组成；长标题最多两行，不只显示编号。

选中关联后显示可点击的引用标签，含类型图标、编号/标题和单独的移除动作。“查看关联”与“移除关联”点击区分开，防止误删。空结果显示“没有找到记录”和明确的新增入口。

## 8. 分析工作台组件

### 8.1 分析记录卡片

卡片结构统一为：**类型与编号 → 标题 → 核心内容 → 关联对象 → 状态或操作**。列表状态显示 2–3 行摘要；展开后显示完整内容与字段。编辑时不在同一个卡片内再套多层带边框卡片。

当前编辑卡片可使用强调边界或轻微选中底色，但正文区域保持白底。记录类型标签放在标题附近，状态放在右侧，二者不能合并。

### 8.2 筛选标签与页签

- 页签切换互斥的内容分类，例如事实分类；选中项用文字加底部标记。
- 筛选标签限制列表范围，例如“待核查”“已归档”；显示结果数量。
- 页签与字段选项必须不同：页签无单选圆点，选项有选择标识，避免用户把切换视图当作填写答案。
- 多选筛选提供清除入口，不默认改变实际分析数据。

### 8.3 列表与表格

普通记录行最低 48px 高，有两行元信息时增至 64px；多行用户文字自然增高。表头背景轻浅、14px 字体；不使用斑马纹和深色粗网格同时强调。

长分析放卡片或展开详情，表格只承担比较与概览。数据为空显示明确提示，不用“—”模糊表示未填写、未知和不适用。

列表行内操作放末尾，重要入口始终可见；次要操作可收进菜单，键盘聚焦时也必须可发现，不只靠鼠标悬停。

### 8.4 状态徽章

| 分析进度 | 样式与标识 | 含义 |
| --- | --- | --- |
| 未开始 | 中性浅底、空圆图标、文字 | 尚无实质内容 |
| 进行中 | 浅靛蓝底、进行图标、文字 | 已输入，尚未复核 |
| 已复核 | 浅绿底、勾选图标、文字 | 完整性检查后组员人工确认 |
| 待复核 | 浅琥珀底、提醒图标、文字 | 已有内容或依据更新，需重新检查 |

保存状态单独使用“正在保存”“已保存及时间”“保存失败”，不复用分析进度徽章。绿色“已复核”也不表示伦理结论被系统判为正确。

### 8.5 引导、缺项和变更提示

普通引导使用中性浅背景或信息浅背景；“待复核”用琥珀浅底并给出“查看变化”入口；保存失败、格式错误等用红色。

缺项检查以可定位的列表呈现：字段名称、具体问题、跳转按钮。正在填写的空字段无需从一开始全部标红；在用户触发检查后显示错误。

同一原因的提示不要同时在顶部、卡片和浮层重复显示。帮助文字不评价用户“思考不足”，只说明当前缺少哪些输入或依据。

### 8.6 来源与参考区

顶部为材料标题和关闭按钮，中间按对象类型显示原内容，底部提供“到原步骤修改”。来源卡片突出标题、作者/年份、位置和摘录，URL 等长字符串允许换行。

引用仅有链接但未核查时明确标注“未核查”。参考区保持次级标题尺寸，不与中央页面标题争夺层级。归档材料显示归档状态，仍能阅读原内容。

## 9. 浮层、抽屉与反馈

| 组件 | 建议尺寸与呈现 | 适用场景 |
| --- | --- | --- |
| 下拉与选择浮层 | 通常 280–360px 宽，列表最大高约 320px | 关联搜索、更多操作；不超出视口 |
| 参考抽屉 | 桌面约 360–400px 宽，窄屏接近全屏 | 查看来源或关联记录 |
| 常规确认对话框 | 最大约 480px 宽，内边距 24px | 覆盖导入、永久删除等有明确后果的操作 |
| 简短反馈 | 桌面右上或右下，移动端居中适配 | 添加成功、归档可撤销等短结果 |
| 字段级错误 | 紧邻控件，不依赖浮层 | 缺项、格式错误 |

导航或详情抽屉在窄屏按覆盖式呈现，提供关闭和返回位置；确认对话框需要明确标题、影响范围和取消按钮。普通编辑仍留在中央区，不为每一段分析弹窗。

可撤销的归档可用约 5–8 秒短反馈，但“撤销”也应能通过归档管理恢复。保存失败和需要用户行动的错误保持可见，不能定时消失。

视觉覆盖顺序：页面内容 → 固定栏 → 参考抽屉 → 选择菜单 → 确认对话框。浮层属于谁就跟随谁，不让底层菜单越过正在处理的确认对话框。

## 10. 主要页面风格模板

| 页面 | 主内容 | 推荐呈现 |
| --- | --- | --- |
| 案例概览 | 背景、成员、进度、继续编辑 | 文档式案例头部 + 精简进度列表，不做堆满图表的仪表盘 |
| 步骤 1 | 三类问题、群体及影响 | 分类页签 + 问题记录列表 + 群体影响表 |
| 步骤 2 | 焦点选择和理由 | 问题选择器 + 判断选项 + 分组说明；候选比较按需展开 |
| 步骤 3 | 分类事实与缺口 | 分类页签 + 来源和核查状态；缺口与事实明确分区 |
| 步骤 4 | 缺口、假设和依据 | 左侧或上方缺口选择 + 假设卡片 + 关联依据 |
| 步骤 5 | 术语定义与澄清 | 术语列表与展开详情；不同理解可并列比较 |
| 步骤 6 | 原则适用与冲突 | 原则卡片或列表 + 单选状态 + 条件展开的理由与冲突区 |
| 步骤 7 | 检查与新增发现 | 可逐项选择的复核清单 + 遗漏发现列表 |
| 步骤 8 | 短期与长期方案 | 桌面并列、窄屏上下；方案状态和依据统一位置 |
| 步骤 9 | 分类约束和方案影响 | 约束列表 + 关联方案详情，不塞入巨大关系图 |
| 步骤 10 | 情景和多类预防措施 | 情景卡片 + 工程/治理/其他措施分区 |
| 来源库 | 来源、类型、核查和引用位置 | 搜索筛选 + 紧凑列表 + 来源详情 |
| 过程与反思 | 迭代记录、截图索引、3 个反思问题 | 日期列表 + 记录详情 + 可独立展开的反思框 |
| 完成检查 | 模板缺项和人工复核状态 | 分组清单，缺项可直接定位，不展示“道德评分” |

## 11. 展示模式

展示模式沿用同一套浅色体系，隐藏编辑控件和密集工具，扩大内容并减少同时显示的记录数量。前 5 步提供快捷导航，全部 10 步仍可访问。

| 内容 | 展示模式规范 |
| --- | --- |
| 页面标题 | 32 / 44px，字重 600 |
| 正文 | 18 / 30px，优先保证投影阅读 |
| 状态与来源 | 不小于 14px；保留事实/假设、未核查等重要标识 |
| 阅读宽度 | 约 880–1040px，按屏幕大小收敛 |
| 长记录 | 展开阅读或由用户选择要展示的片段，不自动生成摘要 |
| 操作 | 仅保留步骤切换、打开来源、退出展示 |

不使用动画背景或大面积渐变；页面切换稳定，避免课堂切换时重排跳动。投影效果需在后续实际设备上确认，不能只按桌面效果判断。

## 12. 状态与空页面

| 状态 | 视觉与文案 |
| --- | --- |
| 无记录 | 简单线性图标、一句说明和新增次级按钮，例如“还没有事实记录” |
| 搜索无结果 | 保留搜索词，显示新增或清除搜索入口 |
| 引用已归档 | 正常阅读文字 + 已归档标签 + 原位置入口 |
| 只读 | 显示阅读内容；不把全文塞进灰色禁用表单 |
| 控件禁用 | 浅灰背景、可读文字，必要时解释为何不可用，不单靠透明度 |
| 保存失败 | 顶部持续提示 + 导出备份入口，当前编辑内容继续可见 |
| 导入需确认 | 对话框列出案例名、时间、条目数和覆盖影响 |

默认空状态不填案例分析示范答案。需要示意内容时，明确写“界面示例”，不能让示例看起来像已录入事实。

## 13. 图标、动效与可访问性

### 图标

采用单一线性图标风格，常规 16px，主要入口 18–20px，笔画约 1.5–2px。使用增加、搜索、来源、关联、检查、提醒、归档等常见含义；不混用彩色 emoji、实心装饰图标和多套线宽。

按钮图标在文字左侧，两者间距 8px。类型标签可以有小图标，主页面无需大型装饰插画。

### 动效

颜色与边界反馈约 120–160ms，折叠区和抽屉约 180–220ms；不使用回弹、夸张缩放或庆祝动画。用户选择减少动效时使用即时或淡入切换。选中后不主动滚动跳页，只有用户定位缺项时才滚动到目标。

### 键盘和阅读

- 焦点轮廓清楚，键盘可到达导航、选项、关联入口、菜单和关闭按钮。
- 单选组、多选组和分段按钮有完整组名及选择状态，不能用纯外观标签代替语义。
- 关闭浮层后返回触发位置；确认弹层与导航抽屉正确处理焦点范围。
- 放大到 200% 时内容可重排，文字与操作不被固定高度截断；表格滚动在自身区域内完成。
- 状态、未知和缺项均有文字说明，不以颜色、声音或悬停提示作为唯一表达。

## 14. 文案与视觉一致性

- 操作名使用具体动词：新增问题、选择来源、查看变化、检查本步、标记已复核、导出备份。
- “请选择”是待输入提示，“尚不确定”是用户判断，二者不合并。
- “未核查”和“待复核”保持区别：前者指材料，后者指已经确认的分析发生变化。
- 案例背景、事实陈述、假设、未来情景统一使用对应标签。
- 帮助提示尽量一到两句；长方法说明放在折叠内容中，当前步骤目标始终可见。
- 顶部保存文案只描述保存状态，不能写成“分析完成”；检查通过只说明字段齐全，仍需人工复核。

## 15. 首版取舍与后续验收

当前支持亮色与深色主题，采用单一默认密度。优先保持一致的导航、字体、点选控件、分析记录、状态提示和参考区；自定义品牌、更多密度和复杂动效不进入本次基础规范。

后续视觉验收清单：

- [ ] 所有页面共用配色和文字层级，没有每一步各自一套风格。
- [ ] 桌面主工作区清楚，参考区可收起，窄屏不挤压表单。
- [ ] 普通文字、提示、按钮和关键控件边界达到本规范的对比度目标。
- [ ] 单选、多选、页签和关联标签外观可区分，选中状态不依赖背景色。
- [ ] 事实、假设、未来情景与核查状态分别呈现。
- [ ] 主要动作克制，新增记录不会与检查按钮争夺多个高强调位置。
- [ ] 选择“其他”可展开自定义内容，切换分支不丢失已写说明。
- [ ] 空、只读、禁用、错误、归档和正常状态均有统一表现。
- [ ] 长中文标题、长来源链接和中英文混排没有截断或溢出。
- [ ] 固定顶部和底部不遮挡输入内容，键盘能定位到所有操作。
- [ ] 200% 放大及窄屏可以完成点选、补说明、查看来源和备份操作。
- [ ] 展示模式可读，并保留必要来源、假设及待核查标识。
- [ ] 深色模式覆盖表单、选择器、菜单、抽屉、确认框与提示，切换不丢失输入，刷新后恢复主题。

本文件是后续页面设计的视觉基线。若需要调整颜色、尺寸或组件表现，应统一修改规范及对应页面，避免局部随意添加新样式。
