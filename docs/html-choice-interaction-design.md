# 10 步分析工具：填空改点选的字段检查与选项清单

本清单配合 [主交互设计](html-interaction-design.md) 使用。本轮只修改设计文档，尚未实现 HTML。

## 1. 检查结论与转换范围

很多分类、状态和关联字段已有明确范围，可以直接用单选或多选；原方案中有些字段虽写了“选择”，还没有定义控件和完整选项，本轮将其具体化。

严重程度的解释、事实陈述、假设内容、术语定义、解决方案和反思回答没有固定答案，适合改为 **先点选整理方向，再补充必要说明**，不能把候选标签当成这些分析题的完整回答。

| 类型 | 判断方式 | 采用控件 | 能否完全替代文字 |
| --- | --- | --- | --- |
| 固定 | 模板或工作流定义了分类/状态范围 | 单选按钮、分段按钮或明确的多选 | 可以替代分类/状态本身；该判断的理由有时仍需文字 |
| 已有记录 | 答案来自当前项目已经登记的对象 | 可搜索单选/多选 + 新增入口 | 可以替代重复填写名称；对象内容仍要创建一次 |
| 开放候选 | 常见方向可列举，但案例答案不能穷尽 | 候选单选/多选 + 其他 + 简短说明 | 只能部分替代；必须保留自定义和具体分析 |
| 开放文字 | 要表达新事实、推理、定义或具体行动 | 短文本或按需展开的长文本 | 保留人工填写 |

“固定”指分类方式或工作流状态可穷尽，不代表伦理答案唯一。所有新增的方向标签都是界面设计选择，不是教师规定的分析结论。

### 每一步能减少哪些填空

| 步骤 | 直接点选的部分 | 点选后补说明的部分 | 仍需写明的内容 |
| --- | --- | --- | --- |
| 1 | 问题分类、已有群体、来源和问题关联 | 群体候选、影响方向、问题方向 | 问题描述、各群体具体影响 |
| 2 | 焦点问题、因果关系、已有受影响群体 | 后果类型、其他选择理由 | 因果依据、严重程度、影响范围、长短期具体后果 |
| 3 | 事实分类、核查状态、负责人、来源 | 缺失信息方向 | 事实陈述、信息缺口及重要性 |
| 4 | 对应缺口、引用事实、假设状态 | 假设依据类型 | 问题、假设陈述、合理性说明 |
| 5 | 关联记录、已有术语和来源 | 术语候选、澄清方向 | 定义、澄清、与案例的相关性 |
| 6 | 课程原则、适用状态、冲突对象 | 冲突处理方向 | 适用/排除理由、冲突与取舍理由 |
| 7 | 检查结果、遗漏类型、处理状态、目标记录 | 后续行动方向 | 遗漏发现、必要依据、行动结果 |
| 8 | 目标问题、责任对象、方案状态 | 短期行动与长期改进方向 | 具体方案和选择理由 |
| 9 | 约束分类、受影响方案、应对状态 | 约束方向、影响方式 | 具体约束、重要性和调整办法 |
| 10 | 关联历史问题、已有群体、措施类别 | 情景变化和预防措施方向 | 新问题、情景、具体预防措施 |

所有按模板要求的重要性说明、案例介绍、3 个反思回答以及报告文字继续由组员自行撰写。点选不能替代要求的 words 数量。

## 2. 共用选择规则

### 控件与默认状态

- 2–6 个固定选项：直接平铺单选按钮；状态用分段按钮，选项较多再用下拉。
- 多选：勾选列表或可点选标签，并显示已选内容；初始不替用户选择实质判断。
- 项目记录较多：搜索 + 编号 + 标题 + 所属步骤，选中后显示关联标签。
- 未选择和“尚不确定”不同：前者没有答，后者是用户明确承认信息不足。
- 新记录可由系统初始化为“待处理”或“未核查”工作流状态，但不能默认成“已核查”“适用”“拟采用”或“无问题”。
- 候选标签不是新增必填项。用户可直接填具体内容，不必先勾所有标签；真正固定的分类和必需状态按原方案检查。

### 其他、不适用与未知

- 开放候选始终支持“其他，自行补充”，选中后才展开自定义名称或方向。
- “无额外理由”“无额外措施”“不适用”“尚不确定”等单独状态与本字段的具体选项互斥，切换时显示实际选择变化。
- “尚不确定 / 待讨论 / 尚未检查”允许保存草稿，但相应必要分析不能据此标记已复核。
- “不适用 / 经检查未发现 / 暂不处理”不是一键跳过：涉及模板内容时展开必要说明。
- “有冲突 / 未发现 / 尚不确定”中的“未发现”必须经过人工检查，不能作为空白字段的自动解释。

### 防止切换导致文字丢失

每个条件分支单独暂存用户文字。例如原则从“适用”切到“不纳入”，保留原适用理由，显示排除理由；再切回可恢复适用理由。当前分析和阅读笔记只使用当前分支，项目备份保留全部暂存分支。选项变化按原设计触发相关步骤待复核。

普通多选的方向标签共用一份具体说明：增删标签保留这份文字，并提示用户检查内容是否仍对应。只有明确互斥的输入分支才分别暂存，不给每个方向标签强制增加一个文本框。

## 3. 步骤 1 的选项

| 字段 | 类型与控件 | 选项或数据来源 | 仍需补什么 |
| --- | --- | --- | --- |
| 问题归属分类 | 固定，单选 | 公司相关 / 工程师相关 / 其他 | 问题标题与具体描述；其他分类不强制再新增分类说明 |
| 问题讨论方向 | 开放候选，多选 | 安全风险 / 信息披露 / 专业责任 / 决策权限 / 利益冲突 / 其他 | 具体行为、责任或价值冲突；此字段为可选辅助 |
| 群体名称 | 开放候选，可搜索单选或自定义 | 员工 / 管理人员 / 供应商 / 客户或用户 / 参与人员或乘员 / 政府监管者 / 当地社区 / 其他 | 可将候选名改成符合案例的具体群体；不预填影响 |
| 已登记利益相关者 | 已有记录，多选 | 本项目群体记录 | 关联即可，不重复填写名称 |
| 影响方向 | 开放候选，多选 | 生命与健康 / 经济与资产 / 权利与自主 / 工作与职业 / 信任与声誉 / 社区与环境 / 其他 / 尚不确定 | 对每个群体写明具体影响；尚不确定状态仍待研究 |
| 影响时间范围 | 固定，单选 | 短期 / 长期 / 两者都有 / 尚不确定 | 不预设具体年限；必要时补时间范围 |

群体候选只提供添加入口：用户选择一个候选、创建记录并写明影响后，才纳入实际分析。不能勾 3 个名称就自动满足模板的“至少 3 类不同利益相关者”。同一实际群体的别名不得重复计数。

## 4. 步骤 2 的选项

| 字段 | 类型与控件 | 选项或数据来源 | 仍需补什么 |
| --- | --- | --- | --- |
| 分析焦点 | 已有记录，单选 | 步骤 1 当前有效问题 | 焦点选择理由按模板完成 |
| 因果关系 | 固定，单选 | 直接 / 间接 / 尚不确定 | 对应依据；尚不确定不能作为已复核的因果分析 |
| 后果类型 | 开放候选，多选 | 生命与健康 / 环境 / 财产与经济 / 权利 / 信任与声誉 / 其他 / 尚不确定 | 说明具体后果和严重程度 |
| 受影响范围 | 已有记录，多选 | 步骤 1 群体 + 新增群体入口 | 群体选择之外，说明范围与规模，不能从名称自动推定人数或地域 |
| 短期、长期后果 | 各用后果类型候选多选 | 复用后果类型；每栏另有“不适用” | 两栏分别写明具体后果，不适用时写原因 |
| 其他选择理由 | 开放候选，多选 | 代表性 / 波及多个群体 / 关联其他问题 / 存在明显价值冲突 / 值得进一步调查 / 其他 / 没有额外理由 | 已有主理由可引用；新增方向如需独立论证则补说明 |

不把“严重程度”直接改成简单的轻/中/重：各组可能用不同标准，同一标签也无法说明具体伤害。先选后果类型，再写具体后果和严重性，能减少起笔困难且保留模板要求。

## 5. 步骤 3 的选项

| 字段 | 类型与控件 | 选项或数据来源 | 仍需补什么 |
| --- | --- | --- | --- |
| 事实分类 | 固定，单选 | 一般 / 物质与技术 / 个人相关 / 组织相关 | 事实陈述；缺失事实在单独区域添加，不能选类别后混作已知事实 |
| 事实核查状态 | 固定，单选 | 未核查 / 已核查 / 存在争议 | 已核查关联来源并人工确认；争议状态填写差异 |
| 来源、相关问题 | 已有记录，多选 | 来源库、问题清单 | 页码/章节按材料填写，未登记可新增 |
| 日期是否已知 | 固定，单选 | 已知 / 未知 / 有争议 | 已知后展开日期或日期范围输入；有争议写明各说法 |
| 缺失信息方向 | 开放候选，多选 | 技术数据 / 决策过程 / 人员行为 / 组织制度 / 时间线 / 其他 | 具体缺什么、为什么重要 |
| 信息缺口进展 | 固定，单选 | 待调查 / 调查中 / 已补充 / 暂无法获取 | 已补充需关联新事实；暂无法获取说明原因 |
| 调查负责人 | 已有记录，单选或多选 | 已登记小组成员 | 不重复输入姓名，允许尚未分配 |
| 某事实分类的检查结果 | 固定，单选 | 有相关事实 / 经检查未发现 / 尚未检查 | 有事实需记录；未发现需必要说明；尚未检查保留待完成 |

日期本身不是选择题，不能只为了减少键入就预设一个日期。可用日期控件或直接引用已录入的日期，但不能把未知日期补成默认值。

## 6. 步骤 4 的选项

| 字段 | 类型与控件 | 选项或数据来源 | 仍需补什么 |
| --- | --- | --- | --- |
| 对应信息缺口 | 已有记录，单选 | 步骤 3 缺口清单 | 新缺口先登记；假设可引用已补充的历史缺口用于回顾 |
| 依据类型 | 开放候选，多选 | 已有事实 / 专业经验 / 逻辑推断 / 其他 | 从哪些内容推导到该假设，不能只写“逻辑推断” |
| 支撑事实与来源 | 已有记录，多选 | 步骤 3 与来源库 | 具体推理仍要写 |
| 假设状态 | 固定，单选 | 暂时采用 / 待核查 / 已被证据否定 / 已由事实替代 | 否定或替代关联新证据，不能自动把假设当作事实 |
| 受影响问题或方案 | 已有记录，多选 | 问题清单、步骤 8 方案 | 可选影响说明 |

“合理假设是什么”没有固定范围，不预填“工程师已充分告知”“管理层明知风险”等案例判断。保留问题、假设和理由三项人工内容。

## 7. 步骤 5 的选项

| 字段 | 类型与控件 | 选项或数据来源 | 仍需补什么 |
| --- | --- | --- | --- |
| 新术语名称 | 开放候选，单选或自定义 | 工程风险 / 专业责任 / 可接受风险 / 安全裕度 / 知情同意 / 其他 | 名称可修改，定义不预填；不把候选视为必选术语 |
| 已有术语 | 已有记录，搜索选择 | 当前术语清单 | 打开已有卡片，避免重复创建 |
| 澄清方向 | 开放候选，多选 | 含义歧义 / 适用范围 / 近义概念 / 角色差异 / 文化语境 / 其他 | 写明本案例采用的含义和具体区别 |
| 定义来源、出现位置 | 已有记录，多选 | 来源库、问题、事实、假设等 | 页码和案例相关性仍由用户填写 |

定义不能用简单的是非题或固定立场题替代。即使点了 3 个候选，仍需每个术语完成定义、澄清和案例相关性，才满足模板要求。

## 8. 步骤 6 的选项

| 字段 | 类型与控件 | 选项或数据来源 | 仍需补什么 |
| --- | --- | --- | --- |
| 分析的伦理原则 | 已有记录，多选或逐项卡片 | 人工确认完整的课程原则清单 | 首次录入原文和出处，之后点选；不凭空编造编号 |
| 适用性 | 固定，逐原则单选 | 适用 / 不纳入 / 待讨论 | 适用或排除理由；待讨论写明争议，保留未完成 |
| 对应问题与依据 | 已有记录，多选 | 问题、事实、假设、来源 | 应用理由仍需人工写明 |
| 是否发现冲突 | 固定，单选 | 发现冲突 / 经检查未发现 / 尚不确定 | 发现后展开冲突卡片；未发现写检查范围和理由 |
| 冲突对象 | 已有记录，多选，至少两个 | 课程原则 + 已登记的其他利益诉求 + 新增诉求入口 | 诉求不能冒充课程原则；填写具体冲突 |
| 处理方向 | 开放候选，单选或自定义 | 尽量兼顾 / 调整方案降低冲突 / 优先满足某项原则 / 其他 / 尚未形成处理意见 | 具体取舍理由；优先原则需另行选择对象 |

不提供“一键全部适用”或“一键全部不纳入并完成”。原则清单可一次载入，适用性仍由组员逐项判断，以免少输入变成少思考。

| 字段 | 类型与控件 | 选项或数据来源 | 仍需补什么 |
| --- | --- | --- | --- |
| 各复核方向的结果 | 固定，单选 | 发现需处理事项 / 经检查未发现 / 尚未检查 | 发现后创建遗漏记录；未发现记录必要依据 |

| 影响位置 | 已有记录，多选 | 各步骤记录 | 不重复填写编号 |
| 后续行动方向 | 开放候选，多选 | 补资料 / 核查来源 / 修订分析 / 新增问题 / 形成方案 / 其他 | 关联目标与行动结果，必要时补具体行动 |

责任主体列表中的小组成员只在方案本来针对课程项目自身时使用；针对历史案例的工程或组织行动应选案例主体，不把填写人误当成实施者。

## 12. 步骤 10 的选项

| 字段 | 类型与控件 | 选项或数据来源 | 仍需补什么 |
| --- | --- | --- | --- |
| 情景变化方向 | 开放候选，多选 | 技术能力 / 自动化程度 / 应用规模 / 参与主体 / 制度环境 / 其他 | 具体未来情景和触发条件 |
| 时间范围 | 开放候选，单选或自定义 | 近期 / 中长期 / 其他时间范围 / 尚不确定 | 必要时自定义时长；不替这些词预设固定年限 |
| 关联历史问题、受影响群体 | 已有记录，多选 | 问题、群体清单 + 新增入口 | 新问题与既有问题的区别 |
| 工程措施方向 | 开放候选，多选 | 改进设计 / 增加检测与监测 / 冗余与防护 / 安全停止机制 / 测试与验证 / 其他 / 不适用 | 针对本情景的具体工程与设计措施 |
| 治理措施方向 | 开放候选，多选 | 标准或准入要求 / 披露与沟通要求 / 独立审查 / 责任与问责机制 / 执行与监督 / 其他 / 不适用 | 谁应要求什么、怎样落实，不预写法律结论 |
| 其他措施方向 | 开放候选，多选 | 组织改进 / 教育培训 / 公众沟通 / 其他 / 无额外措施 | 具体措施；无额外措施不替代工程与治理两栏 |

未来的新问题标题、描述和各类具体预防措施继续人工填写。仅勾“自动化”与“监督”不构成完成了未来问题分析。

| 成员与负责人 | 已有记录，单选/多选 | 案例概览的成员清单 | 姓名只录入一次；贡献描述仍人工写 |

工具设置的 Authority mode、分析视角、使用情境本身也可用固定单选，但按主方案继续列为后续增强，不因本轮字段检查而变成首版新增要求。

## 14. 快速填写路径示例

下面只展示界面步骤，不提供挑战者号事故的分析答案。

```text
新增利益相关者
  ① 选择群体名称，或自定义
  ② 多选影响方向
  ③ 写明这个群体受到的具体影响
  ④ 选择已有来源（可稍后补）
  → 保存一条完整的群体影响记录

处理伦理原则
  ① 从课程原则清单打开一条
  ② 单选：适用 / 不纳入 / 待讨论
  ③ 选择关联问题、事实或假设
  ④ 写明理由
  → 保存该原则的人工判断

制定方案
  ① 选择已有问题
  ② 短期、长期分别点选行动方向
  ③ 分别写明具体行动
  ④ 选择责任主体与依据
  ⑤ 标为候选或拟采用，并写理由
  → 保存方案，供现实约束检查
```

高频关联内容用“最近使用”快捷选择，但不自动勾选；只复用来源、对象与名称，不自动复制上一条记录的伦理判断。

## 15. 保存、导出与验收规则

1. 将分类、状态、所选记录、候选标签、自定义内容、人工说明分别保存，不把整条答案存成无法编辑的拼接字符串。
2. 已有记录按稳定编号保存关联；固定选项需有稳定含义，开放候选可新增，不因标题改名而断开关系。
3. 用户切换选项时保留各分支说明，备份包含暂存内容；阅读笔记只导出当前选项对应的分析，不混入旧分支。
4. 笔记可列出“方向：信息披露”“状态：拟采用”及用户说明，但不能把标签自动扩写成“已经充分披露”或“该方案最优”等报告结论。
5. 分类和状态不重复要求用户手工输入同一标签；“其他”只补自定义部分，关联条目不再重复填写名称。
6. 模板要求的具体分析未填时，即使全部标签已选，也提示缺项；群体、术语与 words 检查沿用主方案。
7. 选择“无 / 不适用 / 尚不确定”后清晰显示互斥结果，切回具体选项能恢复之前的说明，不静默删除。
8. 新增记录能立即在关联选择器中找到；候选群体或术语不会因勾选后放弃保存就计入数量。
9. 纯键盘可完成单选、多选、搜索、新增、自定义和补说明，错误提示定位到具体控件。
10. 点选能否实际节省时间，需要在后续原型中试用；当前不宣称固定完成时长或输入减少比例。

本轮主方案已经同步上述点选方式。后续实现应同时遵守主方案的模板覆盖与本清单的控件/选项规则；本清单不放宽课程要求，也不提供案例的预设最终答案。
